# SQL E-commerce Analysis

Учебный pet-проект по анализу продаж интернет-магазина с помощью **PostgreSQL и SQL**.

**Инструменты:** PostgreSQL, DBeaver, GitHub.  
**Данные:** синтетические, за 2025 год. Все суммы — в условных денежных единицах; результаты не относятся к реальному бизнесу.

## Цель

Исследовать выручку, структуру заказов, популярность товаров и покупательскую активность. С помощью SQL получить бизнес-показатели и сформулировать гипотезы для дальнейшей проверки.

## Данные

В базе содержатся 720 заказов, 150 покупателей, 54 товара, 6 категорий и 1379 позиций заказов.

Связи между таблицами:

- `customers` → `orders` по `customer_id`
- `orders` → `order_items` по `order_id`
- `order_items` → `products` по `product_id`
- `products` → `categories` по `category_id`

Выручка считается только по завершённым заказам (`status = 'completed'`) и по фактическим ценам продажи из `order_items`: `quantity * unit_price`.

## Гипотезы для дальнейшей проверки

1. Исследовать причины возвратов и отмен заказов; в текущем наборе данных этих причин нет.
2. Проверить, как изменение состава корзины и цен повлияло на средний чек между апрелем и июнем.
3. Изучить повторные покупки, частоту заказов и динамику среднего чека.

Это аналитические гипотезы, а не доказанные причинно-следственные связи. Для расчёта прибыли потребуются данные о себестоимости.

## Как запустить

1. Создать в PostgreSQL базу `ecommerce_pet`.
2. Выполнить `01_schema.sql`, затем `02_seed.sql`.
3. Проверить данные с помощью `03_check.sql`.
4. Выполнять запросы из `04_analysis.sql` по отдельности в DBeaver, подключившись к `ecommerce_pet`.

## Использованные приёмы SQL

`JOIN`, `GROUP BY`, `SUM`, `COUNT`, `COUNT(DISTINCT)`, подзапросы, работа с датами, `ROUND`, сортировка и фильтрация. При соединении заказов с позициями используется подсчёт уникальных заказов, чтобы избежать двойного учёта.
